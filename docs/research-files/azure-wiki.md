### Logging Configuration

#### The Logging Stack
vNext logging stack contains two layers:

Layer \#1: ILogger messages are first submitted to the Framework's default logger.  Using standard `{Logging:*}` messages, the framework formats and filter's the message. 
[ILogger Configuration](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/logging/?view=aspnetcore-8.0#configure-logging)

Layer \#2: After the message is accepted by ILogger, the message is passed to Serilog.  Serilog provides additional formatting (usually nothing) and filters the message based on Serilog's filtering rule(s).
[Serilog Configuration](https://github.com/serilog/serilog-settings-configuration)

If the message then passes Serilog's filters, the message is submitted to a configured Serilog store (e.g. Application Insights, console, file) for persitance.

#### Controlling Log Levels

The system ignores the default Microsoft `ILogger<T>` provider. **Always leave the value untouched.**

| Key | Value |
| --- | --- |
| MacroPoint:Shared:Logging:LogLevel:Default | Trace |

---

Serilog is responsible for filtering messages by LogLevel.  

| Key | non-Production<br /><span style="font-size:0.8rem;font-weight:initial">(no label)</span> | localhost | Production<br /><span style="font-size:0.8rem;font-weight:initial">(no label)</span> | Preprod |
| --- | --- | --- | --- | --- |
| MacroPoint:Shared:Serilog:MinimumLevel | Information | Debug | Information | Debug |

#### Ignore Non-Relevant Messages

To hide all messages from a given namespace or class, you override the `SerialLog.MinimumLevel` giving the first part of the [SourceType]`<T>` in the logs.  *If [SourceType] starts with "my.name.space" then log only if those messages are at a specific value.*

Configure a minumum log level on the sink definition when you want to control log levels on a per-sink basis.

Note: Per-sink log levels always operate within the context of the global serilog level default (`Serilog:MinimumLevel`). You can configure the per-sink log level to be more permissive than the global log level, but the messages emitted to the log store(s) follow a most-restrictive pattern between global and per-application log level defintions.

| Sink | Ordinal | Key |  non-Production<br /><span style="font-size:0.8rem;font-weight:initial">(no label)</span> | localhost | Production<br /><span style="font-size:0.8rem;font-weight:initial">(no label)</span> |
| --- | --- | --- | --- | --- | --- |
| Application Insights | 0 | MacroPoint:Shared:Serilog:MinimumLevel | AI is not idependently configurable |

#### Per Application Configuration

MacroPoint applicaitons use a most-recent-wins hierarchical configuration.  To override a logging setting you set a value with a key that is closer to your application.

Settings (e.g. logging minimum level) start at the level they are defined in and continue down the stack until they are overwritten.

For example, given this configuration:
````json
 "Prefixes": [ // listed from most general to most specific
   "MacroPoint:",
   "Shared:", // shared settings across all readers of this store (e.g. connections to shared resources)
   "MacroPoint:Shared:", // settings shared for both client,server,services of MacroPoint system (not other systems e.g. texting)
   "MacroPoint:Api:", // settings for non-client applications. Forms foundation for other systems to override
   "MacroPoint:Alerting:Shared:", // settings shared among all alerting services. Used for most alerting settings. (e.g. serilog reusable core configuration)
   "MacroPoint:Alerting:RuleManager:" // per service specific setting (e.g. appcode, log levels)
 ],
````
The log level is usually set with `MacroPoint:Shared:Serilog:MinimumLevel` and controls logging for any entries from `MacroPoint:Shared` down to `MacroPoint.Alerting.RuleManager`.

If you want to turn on logging for all "Alerting" applications create an Azure applicaton configuration entry like:
````
"MacroPoint:Alerting:MinimumLevel":"<new serlog log level>"
````

If you want to adjust logging for just a single service simply add a serilog log entry to the "RuleManager" configuration hive:
````
"MacroPoint:Alerting:RuleManager":"<new serlog log level>"
````
